# Founder Loop live environment setup

For the credential-free judge demo, follow the [README local run](../README.md#run-locally). Use the steps below when you want to connect your own Discord, Slack and Google accounts.

1. Start a standalone Switch server with Gateway and register a custom agent. Add the agent ID, API key and base URL from that registration to an ignored `.env` copied from [`.env.example`](../.env.example). The demo machine uses the API at `http://127.0.0.1:18000` and Gateway at `http://127.0.0.1:13000`. If the same bot tokens are in use on another Switch server, stop its bridge consumers before connecting them here. See [Switch integration](SWITCH_INTEGRATION.md).
2. Connect Discord and Slack to Switch. Create or pick a Discord intake room and private Slack founder and Product destinations. Add the Slack bridge bot to the channels and invite the custom agent to the mapped Switch rooms. Set the source, founder, Product and founder identity variables in `.env`. Set the native Discord channel and guild IDs for evidence lookup. Keep Switch room IDs and native channel IDs distinct.
3. Set up the Google context. Start with a Product roadmap row on `founder_review` and a concrete decision question. To enable Revenue and Commitment, set `FOUNDER_LOOP_ENABLED_CATEGORIES=PRODUCT,REVENUE,COMMITMENT` and add the private Sales and Support destinations. Add the desired Slack intake rooms, the native Slack source channel map, the category map, the Revenue source roles, and the Leads Sheet ID. Use separate Support source and verdict rooms. See [Google integration](GOOGLE_INTEGRATION.md) for formats and access modes.
4. For interactive Slack cards, create a dedicated app from the [Slack manifest](../slack-founder-app-manifest.json), install it to the same workspace, and invite its bot to the private founder channel. Generate an app-level token with `connections:write`. Set `SLACK_FOUNDER_APP_TOKEN`, `SLACK_FOUNDER_BOT_TOKEN`, `SLACK_FOUNDER_CHANNEL_ID`, and `FOUNDER_SLACK_USER_ID`. The Switch bridge uses its own Slack app. Text decision commands are available when interactive credentials are omitted.
5. With Node.js 22.22.0, run `npm ci` then `npm run live`. The host process uses the `SWITCH_BASE_URL` from `.env`. For the bundled Compose topology, run `docker compose -f compose.agent.yml up -d --build founder-loop-agent` instead. That file expects the standalone Switch service at `http://switch:8000` on the external `founderloop-switch_default` Docker network. For a differently named network or service, adjust the Compose file or use the host command.
6. Send one ordinary qualifying message from an authorized source. Open the exact source link in the private founder card, make a decision, and check that one verdict reaches the correct team room and the founder card closes. See the [test inputs](INTELLIGENCE_E2E.md).

Keep `.env`, Google credential files, the SQLite database and logs local. Use the sanitized [demo script](DEMO_SCRIPT.md) for public capture.
